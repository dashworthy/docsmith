# Building a PDF with @docsmith/docsmith

You turn a source document (a README, a spec, a request) into an A4 PDF that looks designed. You
author it as a small React (`*.pdf.tsx`) module against a fixed component library; the builder
paginates it to PDF with `@react-pdf/renderer` (no HTML, no browser print). Your job is to author it,
**render it, then look at both PDFs** and iterate.

`$SKILL` below is this skill's base directory (shown as "Base directory for this skill" when the
skill is invoked). `$PROJECT` is the directory you are working in (the invoking project's root).

## One-time setup

```bash
cd "$SKILL" && npm install
```

- **Node ≥ 18.**
- **A Chromium-family browser** is needed **only if the document uses `Mermaid`** — auto-detected,
  and used only to rasterize diagrams, never for page layout. A doc with no diagrams needs no browser.
  (See the [README](README.md) for the detection order.)
- Fonts (Inter + IBM Plex Mono) are bundled and embedded — no network needed to render.

## The workflow

### 1. Scaffold a run directory

Create a per-render working directory at the **project root**:

```
$PROJECT/.docsmith/<YYYY-MM-DD>-<slug>/
```

`<slug>` is a short kebab-case handle for the document (e.g. `2026-09-15-api-guide`). The date
prefix keeps every render as its own timestamped directory. You author `pdf.tsx` here and the
rendered PDFs land beside it.

### 2. Author `pdf.tsx`

Write `$PROJECT/.docsmith/<run>/pdf.tsx`. It **default-exports a builder** `(theme) => <PdfDoc …>`,
so one authored document renders in either theme. The builder **may be async**: because react-pdf
renders synchronously, anything async — Shiki code highlighting (`highlightCode`) and mermaid
rasterization (`rasterizeMermaid`) — is awaited **up front** and the result passed to the component
as data.

Import **only** from the bare specifier `@docsmith/docsmith`. Keep the file **self-contained**: no
relative imports, no local asset files — code and diagrams become inline data via `highlightCode` /
`rasterizeMermaid`. (At render time the wrapper stages the file inside the package so the bare
import resolves; a relative import would not survive that.)

```tsx
// .docsmith/<run>/pdf.tsx
import {
  PdfDoc, Cover, Section, P, B, KeyBox, Table, CodeBlock, Mermaid,
  highlightCode, rasterizeMermaid, type PdfTheme,
} from '@docsmith/docsmith';

export default async (theme: PdfTheme) => {
  // Pre-compute async assets before building the tree.
  const setup = await highlightCode('npm install', 'bash', theme);
  const flow = await rasterizeMermaid('flowchart LR\n  A[Start] --> B[(Store)]', theme);

  return (
    <PdfDoc theme={theme} title="My Document">
      <Cover eyebrow="Spec · 2026-09-15" title="My Document"
             lede="One line under the title." chips={['v1', 'Approved']} />
      <Section eyebrow="Overview" title="What this is" deck="A short deck under the title.">
        <P>Body copy with <B>bold</B> where it earns it.</P>
        <KeyBox role="positive" title="Tip">A tip in the positive role.</KeyBox>
        <CodeBlock code={setup} />
        <Mermaid diagram={flow} title="Flow" caption="Start to store." />
      </Section>
    </PdfDoc>
  );
};
```

**No footer, no tool attribution.** This is the reader's document — don't add a "Generated by…" line
or a page footer; put any author, date, or confidentiality metadata on the cover (`CoverPage`'s
`meta` strip or `Cover`'s chips). See [references/authoring.md](references/authoring.md) for why.

**Which component for what** — the full catalog, each with its props and a decision matrix of when
to reach for it, is in **[references/authoring.md](references/authoring.md)**. The fixture
`src/docs/gallery.pdf.tsx` exercises every component and is worth skimming as a worked example
(render it with `npm run gallery`).

### 3. Render — light by default

**Assume the reader wants light** — render `--theme light`. Produce a dark copy (`--theme dark`) only
when the reader asks for one; omit `--theme` to render both at once.

```bash
cd "$SKILL" && node --import tsx src/pdf/render.ts "$PROJECT/.docsmith/<run>" --theme light
```

This reads `<run>/pdf.tsx` and writes **`<run>/pdf-light.pdf`** (`--theme dark` writes
`<run>/pdf-dark.pdf`; omitting `--theme` writes both). A misspelled theme is rejected rather than
coerced; a diagram with bad mermaid syntax aborts the render naming it.

### 4. Verify — always look at the PDF

Do **not** claim success from the exit code alone. Rasterize and inspect both themes, and check
diagrams render as diagrams (fully inside their cards), nothing overflows the page, and there are no
large empty gaps. The full protocol is in **[references/verifying.md](references/verifying.md)**.

Fix and re-render until it holds.
